## Implemented and exercised

- A Character workspace root separate from Persona; mandatory character IDs and
  Character foreign keys on AutoPost content, channels, credentials, sets, views,
  assignments, posts, history, notifications, usage and OAuth state.
- Explicit request/worker context with immutable owner-bound sessions. Scoped ORM
  reads (including IDs/aliases), bulk writes, FK/JSON references and relationships
  are filtered/validated; raw SQL, ownership reassignment and unvalidated ordered/
  batched updates fail closed. Reusing a session after a context switch is rejected.
- Real scoped saved-view create/list/delete API. Missing, malformed, unknown and
  foreign-character IDs are tested. Character creation/list API produces an empty
  workspace with planning/chat flags false and persisted paused/dry-run runtime;
  it does not clone Personas, channels, content or Fanvue credentials.
- AutoChat per-character SQLite storage boundary covering raw-SQL conversation,
  draft, message, memory, PPV, token and account stores. Owner markers and no
  unscoped fallback in character mode. New databases do not seed environment
  credentials. Two mocked rotating Fanvue token chains remain separate, including
  AutoPost's shared credential accessor; foreign Channel ownership is rejected
  before any refresh.
- Namespaced AutoPost state keys; per-character integration snapshots/cache and
  media lifecycle-count cache. AutoChat fan-list, draft-context, insights and
  export-progress caches are partitioned.
- Per-document URL context and responsive character switch/create controls in
  both HTML shells. No localStorage/cookie active-character selection. Same-origin
  fetches, links/forms and local redirects retain the document's owner. Switching
  navigates to a fresh document instead of mutating a global active workspace.
- Per-character media directories and media SHA uniqueness; owner-qualified file/
  thumbnail URLs; authenticated file/thumbnail routes, private/no-store responses
  and original-file path containment. Synchronous chat exports and group-export
  thread ownership are namespaced.
- Immutable character ownership on in-process long-running runs, scoped lookup/
  progress/cancel, explicit owner propagation in their async wrapper and an
  owner-carrying thread helper. Real fan-list refresh and group-export threads use
  the helper. An unowned run/thread is rejected when character mode is enabled.
- A real SQLite offline-copy migration/preflight tool with explicit existing-name
  assignment, source preservation, output receipts/hashes, idempotent repeat,
  per-character SHA-index conversion and nested-path protection. It was exercised
  only with disposable synthetic databases/media. See `character-migration.md`.
- Existing Europe/Berlin midnight-gate and daily-total-quota implementations were
  preserved unchanged and their focused regression tests pass.

Strict RED/GREEN evidence for the implemented feature slices is retained in the
handoff evidence directory. Additional already-working behavior was checked with
provider mocks. There was no independent reviewer approval and no `[verified]`
implementation commit; the parent must review the patch before integration.

## Incomplete acceptance criteria / release blockers

This is **not** the approved comprehensive architecture completed end-to-end.
The following remain open and prohibit production activation:

1. Normal application lifespan/startup and scheduler fan-out are still legacy.
   Both scheduler backends need explicit persisted character dispatch, immutable
   Celery payloads and per-character daily-gate/lease coverage. An enabled-mode
   unscoped DB access fails closed; that is not a working multi-character startup.
2. AutoChat poller/watchdog are still singleton workers. Memory-backfill and
   purchase-import background threads/status require the same owner propagation
   and partitioning. A scoped database alone does not complete these worker paths.
3. Global technical settings vs character settings are not fully separated.
   AutoPost process-global runtime flags and some settings mutation paths remain
   shared; account-specific environment fallback and global technical inheritance
   need a reviewed policy. New persisted safe defaults do not prove all runtime
   switches are independently enforced.
4. OAuth callback re-entry must recover the immutable character from signed/state-
   bound pending OAuth data without an active-character cookie. All providers,
   connection tests, background refresh/status caches, publisher media staging,
   watermark paths and export/upload chains still need a complete ownership audit.
5. AutoChat direct draft/fan action IDs and all settings/forms have not been
   exhaustively exercised with two accounts. ORM FK checks prevent cross-owner
   references in scoped sessions, but all legacy route contracts/error mappings
   and pairwise DB constraints are not fully migrated. Persona slug uniqueness
   remains global. Thumbnail symlink containment needs additional hardening.
6. In-flight fan-list coordination and several process/thread status holders
   remain global even though returned content caches are partitioned. Retention,
   metrics/manual jobs and every hidden service cache need individual scope tests.
7. GUI-updater migration/rollback activation, PostgreSQL migration, source-schema
   variants with inline SHA UNIQUE constraints, and real downstream single-
   character upgrade packaging have not passed acceptance. The archive is a source
   review artifact, not a release/update package that may be published.
8. Browser checks cover the actual new script with offline fixtures (two tabs,
   switch, scoped fetch/link behavior and 320/390/1280 widths), not exhaustive
   media/set/channel/calendar/dashboard/analytics/settings editing workflows.
   Current test fixtures do not establish complete production UI acceptance.

Do not enable `MP_CHARACTERS_ENABLED=1` on a live installation or run this as an
update. Continue the above tasks under TDD on the separate source tree, then
repeat security, route, provider, migration, update-preservation and browser
coverage before requesting production authorization.
